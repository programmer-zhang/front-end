# JS 中的按位运算

### 写在前面
> 在[《JS 浮点数计算》](./js浮点数计算.md)一文的「解决方式」中提到"浮点数转化成整数再进行计算"，而 JS 中最快的整数化手段就是按位运算（`x | 0`）。按位运算看似底层冷门，实际上它是理解 JS 数值系统的一道必经之路：它强制把 64 位浮点数**截断成 32 位整数**再运算。本文系统梳理 JS 的 7 个位运算符、背后的 ToInt32 转换规则，以及实战中真正常用的技巧。

## 阅读本文您将收获
* JS 按位运算的 7 个运算符及运算规则
* 按位运算前隐式发生的 `ToInt32` 转换（含 NaN、Infinity、超出范围的浮点数如何被处理）
* 位掩码、权限系统、Hash 等实战用法
* 按位运算做整数化的能力边界与陷阱

## 前置知识：为什么是 32 位

> JS 的 `Number` 是 64 位双精度浮点数（见母文章），但**所有位运算符都会先把操作数转换为 32 位有符号整数**，运算完成后再把结果转回 64 位浮点数存储。

* 这个转换是 ECMAScript 规范中的抽象操作 **`ToInt32`**，规则如下：
	1. `ToNumber` 转为数值（字符串、布尔等先转数字）。
	2. `Math.trunc` 截断小数部分（**向零舍入**，不四舍五入）。
	3. 取数值对 `2^32` 的模，映射到 `-2^31 ~ 2^31 - 1`。

```js
12.9  | 0;        // 12   （截断，非四舍五入）
-12.9 | 0;        // -12  （向零舍入，与 Math.floor(-12.9) === -13 不同）
NaN   | 0;        // 0
Infinity | 0;     // 0
'3.7' * 1 | 0;    // 3
2 ** 32 | 0;      // 0   （对 2^32 取模）
2 ** 31 | 0;      // -2147483648 （溢出回绕到符号位）
```

* ⚠️ **能力边界**：超过 32 位的整数会被"回绕"。安全整数范围是 `2^53 - 1`，但位运算只能安全处理 `2^31 - 1` 以内的数值——大数场景（如雪花 ID、金额分为单位的大数值）慎用位运算。

## 七个位运算符

> 以下均以 8 位为例展示，实际运算发生在 32 位上。

### 1. 按位与 `&` —— 双 1 为 1

```
  0b1010  (10)
& 0b0110  (6)
-------
  0b0010  (2)
```

* 任何位与 `0` 相与得 `0`，与 `1` 相与保持不变 —— 这是**掩码（mask）** 的基础。
* 常用于：取特定位、判断某位是否为 1。

### 2. 按位或 `|` —— 有 1 为 1

```
  0b1010  (10)
| 0b0110  (6)
-------
  0b1110  (14)
```

* 任何位与 `1` 相或得 `1` —— 常用于**合并标志位**、强制置 1。
* `x | 0` 中 `0` 不改变任何位，只承担 ToInt32 转换，所以成为最快的"取整"写法。

### 3. 按位异或 `^` —— 不同为 1

```
  0b1010  (10)
^ 0b0110  (6)
-------
  0b1100  (12)
```

* 性质：`a ^ a = 0`，`a ^ 0 = a`，满足交换律和结合律。
* 常用于：不借助临时变量交换两个数、找唯一出现的数。

```js
// 交换变量（不引入第三个变量）
let a = 1, b = 2;
a ^= b; b ^= a; a ^= b;   // a=2, b=1

// 数组中只出现一次的数（其余都出现两次）
[4, 1, 2, 1, 2].reduce((acc, n) => acc ^ n, 0);   // 4
```

### 4. 按位非 `~` —— 逐位取反

```
~ 0b1010  =>  0b1111...0101  (32 位下 = -11)
```

* 规范定义 `~x === -(x + 1)`，所以 `~0 === -1`。
* 经典技巧：`indexOf` 返回 `-1` 表示不存在，而 `~-1 === 0`（falsy）：

```js
// 旧代码中常见的写法（等价于 !== -1）
if (~str.indexOf('x')) { /* 找到了 */ }

// 现代写法直接用 includes，可读性更好
if (str.includes('x')) { /* 找到了 */ }
```

* `~~x` 是双重取反，效果同 `x | 0`：截断取整，且速度通常更快。

### 5. 左移 `<<` —— 低位补 0

```
  0b00001010  << 2  =>  0b00101000
  10 << 2 === 40        （相当于 10 * 2^2）
```

* 溢出符号位时会变负数：`0b01000000000000000000000000000000 << 1 === -2147483648`。

### 6. 有符号右移 `>>` —— 保持符号位（算术右移）

```
  0b11111010  >> 2  =>  0b11111110
  -6 >> 1 === -3        （高位补符号位，负数仍为负）
```

* 等价于 `Math.floor(x / 2^n)`（注意是**向 -∞**，负数时与截断不同）：

```js
-5 >> 1;          // -3  （-5 / 2 = -2.5，向 -∞ 取 -3）
Math.trunc(-5/2); // -2  （向零，两者不同！）
```

### 7. 无符号右移 `>>>` —— 高位补 0（逻辑右移）

```
  0b11111010  >>> 2  =>  0b00111110
  -6 >>> 1 === 2147483645   （高位补 0，负数变正数）
```

* `x >>> 0` 会把 ToInt32 的结果再转成 `0 ~ 2^32 - 1` 的无符号数，常用作 **`length` 归一化**：

```js
// 类数组转数组的经典 hack：把 length 转成真正的无符号整数
Array.prototype.slice.call(arguments);
// 或者
Array.from({ length: '5' >>> 0 });   // length: 5
```

## 核心应用：位掩码与权限系统

> 一个 32 位整数的每一位都可以当做一个独立开关，一次运算同时操作 32 个布尔状态——这是位运算最经典的工程应用，`fs` 模块的权限位、`JSON.stringify` 第三个参数的历史用法、Linux 权限 `chmod 755` 都是这个思路。

```js
// 定义权限位（每 bit 一种权限）
const READ  = 0b0001;   // 1
const WRITE = 0b0010;   // 2
const EXEC  = 0b0100;   // 4
const ADMIN = 0b1000;   // 8

let user = 0;
user |= READ | WRITE;               // 授予：读 + 写  => 0b0011
user &= ~WRITE;                     // 收回：写      => 0b0001
user ^= EXEC;                       // 切换：执行    => 0b0101

const canRead  = (user & READ)  !== 0;   // true
const canWrite = (user & WRITE) !== 0;   // false

// 组合权限的判断：是否同时拥有 READ 和 EXEC
const hasAll = (user & (READ | EXEC)) === (READ | EXEC);   // true
```

* 优点：一个数字即可存储/传输 32 个状态，判断、增删权限都是 O(1)。
* 注意：这种用法只适合**状态之间无依赖、数量有限**的场景；状态过多时枚举对象更可读。

## 其他常用技巧

```js
// 1. 取整（ToInt32 截断，注意 32 位和负数语义）
~~3.7;        // 3
3.7 | 0;      // 3
~~(-3.7);     // -3  （不是 -4，与 Math.floor 不同）

// 2. 判断奇偶（比 n % 2 更快且不受负数符号影响）
n & 1;        // 1 奇数，0 偶数

// 3. 乘除 2 的幂
n << 1;       // n * 2
n >> 1;       // 向下取整的 n / 2

// 4. 求平均值（防溢出写法：先各自折半再合并）
(a & b) + ((a ^ b) >> 1);

// 5. 快速判断两数符号是否相同
(a ^ b) >= 0;   // >= 0 同号，< 0 异号

// 6. 取相反数
~-5;          // 5
```

## 位运算与浮点数：和母文章的连接

> 回到母文章「解决方式」第 1 条——浮点数转整数。位运算正是借 ToInt32 的**向零舍入**完成这一步的：

```js
// 经典的"分为单位"整数运算法，配合位运算
const price = 19.9;
const count = 3;
const total = (price * 100 | 0) * count;   // 1990 * 3 = 5970
total / 100;                               // 59.7，规避了 19.9 * 3 = 59.699999999999996
```

* 但要清楚：`| 0` 的取整是**向零截断**（见《IEEE 754 的四种舍入方向》中的"向零舍入"），`Math.round` 是平局向上、`Math.floor` 是向 -∞——**同一个数，不同取整方式结果不同**，按业务语义选择。

| 表达式 | 2.5 | -2.5 | 语义 |
| --- | --- | --- | --- |
| `Math.floor(x)` | 2 | -3 | 向 -∞ 舍入 |
| `Math.ceil(x)` | 3 | -2 | 向 +∞ 舍入 |
| `Math.trunc(x)` / `x \| 0` / `~~x` | 2 | -2 | 向零舍入（截断） |
| `Math.round(x)` | 3 | -2 | 平局向 +∞ |
| IEEE 754 默认舍入 | 2 | -2 | 平局取偶（内部自动） |

## 注意事项
* **32 位限制**：`2^31` 以上的安全整数经位运算会回绕成负数；`Number.MAX_SAFE_INTEGER` 附近的数值禁止使用位运算。
* **可读性优先**：现代 JS 中 `Math.trunc`、`Math.floorDiv` 类逻辑、`includes` 等已能替代大多数位运算 hack，位运算应保留给真正需要它的场景（掩码、Hash、性能敏感代码）。
* **不要用 `^` 做幂运算**：`2 ^ 3 === 1`（异或），幂运算用 `**` 或 `Math.pow`——这是最常见的位运算符误用。

## 解决方式
1. 需要取整时优先明确语义：向零用 `Math.trunc`，向下用 `Math.floor`；位运算写法仅在热点代码中使用。
2. 多状态开关、权限模型用位掩码存储，一个数字管理 32 个布尔值。
3. 涉及金额先转为整数（乘 100 取整）再运算，规避浮点误差，收口时再除回。
4. 算法题中活用异或的性质（`a ^ a = 0`）解决"只出现一次的数"、"交换变量"类问题。
